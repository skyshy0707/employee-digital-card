---------- Тестовое задание ----------

Смысл тестового задания в том, чтобы Вы продемонстрировали навык использования всех перечисленных технологий. Время на выполнение тестового задания не ограничено. Упор на качество. Убедительная просьба – либо отнеситесь к тестовому заданию серьезно, либо не беритесь за него вовсе.

Создайте Вашу цифровую визитку (backend-приложение), которая презентует Вас как специалиста, с обязательным использованием следующих технологий:
- Git;
- TypeScript;
- Node.js;
- NestJS;
- Prisma;
- GraphQL;
- Docker.

Приложение должно предоставлять Apollo Sandbox (GraphQL Playground), через которое можно получить информацию о Вас, Вашем опыте работы, навыках и проектах.

Бэкенд должен содержать:
1. Профиль:
- имя;
- краткое описание;
- ссылки на GitHub/LinkedIn или другие профессиональные ресурсы.

2. Список навыков.

3. Опыт работы:
- компания;
- должность;
- период работы;
- Ваши достижения.

4. Проекты:
- название;
- ссылка на проект/репозиторий.

При запуске приложения база данных должна быть автоматически подготовлена и заполнена Вашими данными.

API должно позволять получить профиль и связанные с ним данные, например:

query: {
    profile: {
        name: String,
        description: Text,
        links: List<Link{
            url: UrlString,
            provider: String
        }>,
        skills: List<JSON<{
            name: String as Skill.name
        }>>,
        experience: List<{
            company: String as Position.company.name,
            position: String as Position.job.name,
            period: JSON<Period>,
            achievments: ListField<String>: 
        }>,
        projects: List<{
            name: String as Project.name,
            company?: String as Project.experience.job.company.name
        }>
    }
}

Модели реляционной схемы:

Profile: {
    id: Id,
    name: String,
    description: Text,
    skills: m2m<Skill>,
}


Skill: {
    id: Id,
    name: String,
    profiles: m2m<Profile>
}

Link: {
    id: Id,
    profile_id: Profile.id,
    url: UrlString,
    provider: String, computed
}

Company: {
    id: Id,
    name: String
}

Job: {
    id: Id,
    name: String
}

Position: {
    company_id: Company.id,
    job_id: Job.id
}

Experience: {
    id: Id,
    profile_id: Id, 
    position_id: Position.id,
    period: JSON<Period>,
    achievments: ListField<String>
}

Project: {
    id: Id, 
    link_id: Link.id,
    name: String,
    experience_id?: Experience.id
}



Конкретную структуру GraphQL API, базы данных и архитектуру приложения выберите самостоятельно. Обоснуйте принятые архитектурные решения в README.md файле.

Бизнес-логика, работа с данными и GraphQL API должны иметь разумное разделение ответственности.

Что оценивается:
- в первую очередь оценивается не количество написанного кода, а качество инженерных решений.

Обратите внимание на:
- структуру приложения и разделение ответственности;
- работу GraphQL с вложенными данными для оптимизации запросов к базе данных;
- взаимодействие с базой данных;
- инициализацию и заполнение базы данных;
- читаемость и поддерживаемость кода;
- корректную работу приложения после запуска с нуля.

Просим предоставить:
1. Ссылку на проект (для просмотра). Бэкенд можете попробовать развернуть на Vercel/Render/Railway или любым удобным для Вас способом;
2. Ссылку на Git (для ознакомления с исходным кодом).
